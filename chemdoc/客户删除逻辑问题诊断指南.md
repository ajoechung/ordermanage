# 客户删除逻辑问题诊断指南

## 问题描述
客户列表删除时，没有弹出确认框，直接删除了。

### 后端代码 (backend/app/service/CustomerService.php)
```php
public function delete(int $id, bool $force = false): array
{
    // 1. 检查权限
    if (!DataScopeService::canAccessCustomer($id)) {
        return Result::error('无权访问此客户');
    }
    
    // 2. 检查客户是否存在
    $customer = CustomerModel::find($id);
    if (!$customer) {
        return Result::notFound('客户不存在');
    }

    // 3. 检查是否有订单（未删除的订单）
    $hasOrders = Db::name('order')
        ->where('customer_id', $id)
        ->whereNull('delete_time')
        ->count();
    if ($hasOrders > 0) {
        return Result::error('该客户存在订单，无法删除');
    }

    // 4. 检查是否有联系人
    $hasContacts = Db::name('contact')->where('customer_id', $id)->count();
    if ($hasContacts > 0) {
        if (!$force) {
            // 没有强制删除，返回201，要求确认
            return [
                'code' => 201,
                'msg' => '该客户存在联系人，确认删除将同时删除所有联系人',
                'data' => ['contact_count' => $hasContacts]
            ];
        }
        // 强制删除，删除联系人
        Db::name('contact')->where('customer_id', $id)->delete();
    }

    // 5. 删除客户
    $customer->delete();

    // 6. 记录日志
    OperationLogModel::log(
        request()->user_id ?? 0,
        request()->username ?? '',
        '客户管理',
        '删除',
        '删除客户：' . $customer->name
    );

    return Result::success(null, '客户删除成功');
}
```

## 可能的问题及排查步骤

### 问题1：后端代码没有更新到服务器

**排查步骤：**
1. 登录服务器
2. 检查后端代码文件的时间戳
   ```bash
   cd /www/wwwroot/chemdoc
   ls -la backend/app/service/CustomerService.php
   ```
3. 对比GitHub上的提交时间
4. 如果服务器代码较旧，执行：
   ```bash
   git pull origin main
   ```

### 问题2：前端代码没有更新到服务器

**排查步骤：**
1. 检查服务器上的前端JS文件
   ```bash
   ls -la /www/wwwroot/chemdoc/frontend-dist/assets/
   ```
2. 查找包含 "handleDelete" 或 "contact_count" 的文件
   ```bash
   grep -r "contact_count" /www/wwwroot/chemdoc/frontend-dist/assets/
   ```
3. 如果没有找到，说明前端代码需要重新构建并部署

### 问题3：客户确实没有联系人

**排查步骤：**
1. 登录数据库服务器
2. 检查客户是否有联系人
   ```sql
   SELECT c.customer_id, c.name, COUNT(ct.contact_id) as contact_count
   FROM customer c
   LEFT JOIN contact ct ON c.customer_id = ct.customer_id
   GROUP BY c.customer_id, c.name
   HAVING contact_count > 0
   ORDER BY customer_id DESC
   LIMIT 10;
   ```
3. 如果客户没有联系人，后端会直接返回 `code=200`，不弹出确认框是正常的

### 问题4：浏览器缓存了旧的前端代码

**排查步骤：**
1. 打开浏览器开发者工具（F12）
2. 禁用缓存（勾选 "Disable cache"）
3. 刷新页面（Ctrl+Shift+R）
4. 再次测试删除功能

## 正确的删除流程

### 场景1：客户有联系人
1. 用户点击"删除"按钮
2. 前端调用 `DELETE /api/customer/{id}`（不带force参数）
3. 后端检查发现客户有联系人，返回 `code=201`
4. 前端弹出确认框："该客户存在 N 个联系人，确认删除将同时删除所有联系人，确定继续吗？"
5. 用户点击"确定删除"
6. 前端再次调用 `DELETE /api/customer/{id}?force=true`
7. 后端删除联系人，然后删除客户
8. 返回 `code=200`，前端显示"删除成功"

### 场景2：客户没有联系人
1. 用户点击"删除"按钮
2. 前端调用 `DELETE /api/customer/{id}`
3. 后端检查发现客户没有联系人，直接删除
4. 返回 `code=200`，前端显示"删除成功"

### 场景3：客户有订单
1. 用户点击"删除"按钮
2. 前端调用 `DELETE /api/customer/{id}`
3. 后端检查发现客户有订单，返回错误
4. 前端显示错误消息："该客户存在订单，无法删除"
